# Firmware completion-latch acceptance matrix

**Phase:** Acceptance design only. This document defines expectations independently of the firmware implementation.

**Authority:** The 2026-09-16 consolidated completion-latch contract in `.squad/decisions.md`, the related bridge acceptance decisions, and Vadim's firmware acceptance request. Bridge tests provide the acceptance-suite pattern and wire examples; they do not define firmware behavior.

## Verification classes

- **Host:** Deterministic assertion in the C++ host suite after the harness gains the seam described below.
- **Fixture:** Serialized JSON generated by the real bridge snapshot pipeline and consumed by the C++ host suite.
- **Manual:** Physical M5Dial check. The host suite still verifies the render or input decision that precedes the physical effect.

## Existing host-harness coverage

The current `firmware/test/run-host-tests.sh` compiles one dependency-light C++ binary with ArduinoJson and plain assertions. It already provides useful foundations:

- Real bridge-generated `sv/ss` fixture consumption.
- Strict 12-lowercase-hex session IDs, bounded species/state values, exact five-color palettes, and malformed-row skipping.
- Parse-failure non-mutation for truncated JSON.
- UTF-8 decoding, byte clamps, display flattening, wrapping, and fixed-buffer guards.
- Stable selection by session ID across reorder, disappearance fallback, and encoder stepping.
- Persona mapping, palette mapping, prompt attention-floor helpers, display-mode fallback, and record-size limits.
- Source-level catalog invariants that protect the bridge-to-firmware species index.

These checks cover reusable primitives, but they cannot currently call `data.h` or `main.cpp`, inject time or hardware events, observe BLE commands, or inspect the selected presentation surface. They therefore cannot prove the completion-latch contract as an integrated pipeline.

## Required harness gains

1. **Dependency-free latch core.** Compile the completion mirror as a C++ header or source with no M5Dial, BLE, `Stream`, display, or ESP dependencies. Expose a canonical state snapshot containing visibility, epoch, generation floor, outcome, copied owner metadata, latch time, intro-consumed/settled phase, legacy priming, connection state, and pending acknowledgement.
2. **Atomic JSON adapter seam.** Move `sg/sc` presence/type validation behind a callable adapter that accepts `JsonVariantConst`. It must distinguish absent `sc` from explicit null and publish only a fully validated temporary candidate. Extend the real bridge fixture generator with valid, degraded ownerless, malformed, missing-`sc`, stale-generation, and changed-epoch lines.
3. **Unsigned time injection.** Pass `uint32_t now` into every transition or provide an injected `millis` provider. Tests must place time on both sides of rollover and inspect event boundaries at 400, 800, 5,600, 150, and 86,400,000 ms without sleeping.
4. **Connection and transport fake.** Inject BLE connected edges independently of snapshot arrival. Capture outbound JSON commands as parsed objects and model write failure, disconnect-before-ack, reconnect, resend, authoritative clear, and generation replacement.
5. **Input event fake.** Represent button down/held/release/click, encoder delta/fast-spin, touch down/contact/up plus coordinates, and screen power state. Drive events across multiple loop frames so the wake-consumption state machine, long-press threshold, and quiet window are testable.
6. **Render-decision introspection.** Extract a pure resolver that returns the winning surface (`ota`, `passkey`, `prompt`, `attention`, `completion`, `live`, `aggregate`, `idle`), completion badge, species source, palette source, outcome ring, animation phase, dismissal visibility/hit target, and independent chirp/ring facts. The host suite should assert this structure rather than scrape drawing calls.
7. **Effect sinks.** Count celebrate-frame transitions, confetti, chirps, tones, invalidations, and dismissal sends. This makes “exactly once” and “fully still” mutation-sensitive without pixel snapshots or speakers.
8. **Carousel-state probes.** Provide read-only accessors or a composed UI model for selected ID/index, `lastCarouselMs`, prior-row history, and the live `SessionPalSet`. Completion tests must prove those values do not move.
9. **OTA/passkey/prompt fakes.** Inject those facts without including their hardware stacks, and expose transition order so OTA-begin clear and modal hide/reveal behavior are deterministic.
10. **Status-ack formatter test.** Compile the real status JSON construction or a shared capability-data helper on the host. The acceptance suite must not settle for testing a duplicate constant.
11. **End-to-end host rig.** Compose JSON input, latch core, connection fake, presentation resolver, input guard, and command sink in one fixture. Unit tests catch local mutations; the rig catches unwired pipeline legs.

## Hardware-only checklist

The host suite can prove decisions and emitted effects, but the following require the physical M5Dial:

- Touch hit-target usability and calibration around the completion pill on the round display.
- Button short-click versus 600 ms long-press feel, including wake-through-release behavior.
- Encoder residual counts and touch-controller contact tails during the approximately 150 ms quiet window.
- Actual BLE disconnect/reconnect timing, notification loss, and acknowledgement resend against the desktop bridge.
- Exact 5.6-second species animation appearance, final-pose stillness, no tearing after prompt/passkey closure, ring legibility, confetti absence, and badge/color contrast.
- Audible success/failed/aborted behavior and absence of repeated chirps once settled.
- OTA begin while a completion is visible, without flashing in this acceptance-design phase.

## Highest-risk predicted defects

1. **Absent-versus-malformed collapse.** ArduinoJson APIs can make an absent member and explicit null look similar. Treating both as authoritative clear would repeat the bridge's malformed-input boundary failure in a more destructive form.
2. **Partial candidate publication.** Parsing `g/o` into live state before validating `i/p/c/m/d` can leave a new generation paired with stale owner metadata. The bridge review already found that optional tuple validation needed explicit hardening.
3. **Capability advertised before the last pipeline leg.** `cl:1` disables the bridge's safer legacy path. A parser-only or renderer-only implementation can strand a terminal card or lose dismissal across reconnect.
4. **Edge identity based on level, index, or raw bytes.** The bridge's startup-baseline ambiguity and cross-session ID collision show how plausible edge detection false-latches history or misses real new work. Firmware legacy detection is vulnerable to the same class through startup `completed:true`, reordered rows, and reused array positions.
5. **Reconnect resurrection and animation replay.** Clearing all state on disconnect permits the same epoch/generation to look new; preserving all state can leave a stale card visible while disconnected. Visibility, suppression floor, intro consumption, and pending ack must be separate facts.
6. **One-frame wake suppression.** The existing input path was already identified as insufficient for multi-frame button, encoder, and touch gestures. Delayed release/click events are likely to dismiss or open menus after wake.
7. **Signed or deadline-based rollover bugs.** The 24-hour watchdog is shorter than half the uint32 range and is safe with unsigned subtraction, but signed comparisons or `start + duration` deadlines fail near rollover.
8. **Priority implemented only in drawing.** A hidden completion may remain actionable behind a prompt, passkey, menu, or clock if rendering and dismissal use different visibility predicates.
9. **Live-row aliasing.** Reusing `SessionPalSet` storage or carousel selection for completion metadata will lose the owner as soon as the ended row disappears and will perturb selection timestamps.
10. **Effect loops after settle.** Reusing `P_CELEBRATE` without a latched phase boundary can keep confetti, chirps, invalidations, or animation ticks alive indefinitely, or replay them after a modal.
